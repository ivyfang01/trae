# 养殖技术服务工具 · 范围草稿

## 一、需求背景（PRD）

为激发技术老师**主动拜访**的能动性，并让客户真实感知到**粮巴巴的技术服务**，技术老师在拜访客户后需填写规范的**巡场报告**，并将报告发送给客户。

通过「上门服务 → 规范留痕 → 报告触达客户」，体现粮巴巴的真诚服务，从而**提升客户粘性**。

| 维度 | 说明 |
| --- | --- |
| 对内（老师） | 用标准化巡场报告降低填写随意性，把主动拜访变成可完成、可沉淀的工作动作 |
| 对外（客户） | 客户能收到可读的服务报告，感知「有人持续在服务我」，而非仅线下口头沟通 |
| 品牌 | 强化粮巴巴技术服务形象与信任感 |

### 要解决的问题
1. 技术老师拜访动作缺少统一、规范的输出物，主动服务难量化、难复盘。  
2. 客户侧缺少可感知的服务触达，难以形成「被持续服务」的体验，粘性不足。

### 目标用户
| 角色 | 用途 |
| --- | --- |
| 养殖技术老师 | 主用户；拜访后填写规范巡场报告，并发送给客户 |
| 客户群相关人 | 接收企微卡片摘要；被 @；感知粮巴巴技术服务 |

### 成功指标（MVP）
- 先看：**发送到客户企微群的卡片数量**（服务触达次数 / 主动服务留痕）
- 客户阅读量：本期先不做强依赖，后续可加

## 二、已确认范围

### 1. 客户侧触达
- 发到**客户企微群**
- 群内：**卡片摘要** + **@ 指定人员**
- 可点进看详情（完整报告）

### 2. 老师侧能力
- 首次填写、二次拜访、查看
- **二次拜访必须带出上次未解决问题，并确认是否已解决**
- 大结构：基础信息 → 鸡群信息 → 场舍检查维度 → 问题汇总 / 追踪卡 → 处理方案 → 现场签到 → 分享

### 3. 细节维度（A ∪ B）
**A 摸底/指标型：** 产蛋率、体重/均匀度、温湿度、通风、精神状态、蛋品情况、粪便、喂料情况、供水、加药情况、卫生、粉尘、饲料仓储情况、场外环境情况、其他  

**B 驻场巡查型：** 巡舍工作、环控设施、精神状态、采食状况、水线状况、死鸡状况、卫生检查、产蛋及蛋品、其他工作  

> 注：精神状态、通风/环控、蛋品、卫生等有交叉，方案里做**去重合并为一套维度清单**，避免重复填写。

### 4. 实现平台
- **H5 填写**（老师端）
- 分享到企微客户群（卡片）

### 5. 现有/竞品

### 6. MVP / 暂不做
**MVP：** H5 规范巡场填报 + 问题追踪 + 二次拜访未解决问题确认 + 企微卡片发送给客户 + @人 + 统计发送卡片数  

**暂不做：** 强依赖客户阅读量分析；复杂数据看板；非企微渠道

## 三、方案框架（草案）

### 信息架构
```
报告列表
  ├─ 新建报告（选客户/场舍/服务类型：首次|回访|驻场…）
  ├─ 编辑中 / 已发送
  └─ 查看

报告编辑（H5）
  ① 基础信息
  ② 鸡群信息
  ③ 各维度详细说明（A∪B 去重后的清单；正常/异常 + 问题描述）
  ④ 问题汇总（各维度异常汇总后展示）
  ⑤ 服务问题追踪卡（现场问题 + 是否解决）
  ⑥ 处理方案
  ⑦ 现场签到等
  └─ 分享 → 生成企微卡片并 @指定人 → 发送客户，完成服务触达

二次拜访进入时
  └─ 「服务问题追踪卡」：来自该客户上次未解决项 → 逐条确认已解决/仍未解决
```

### 主流程
1. 技术老师主动拜访客户  
2. 打开 H5 → 选客户与场舍 → 按规范填写巡场报告  
3. 若存在历史未解决问题 → 先确认状态  
4. 预览卡片摘要 → 选 @人 → **发送到客户企微群**  
5. 客户感知粮巴巴技术服务；系统记一次「发送卡片」  

### 企微卡片摘要建议字段
- 标题：养殖服务报告 · {场舍}  
- 服务日期、技术老师  
- 异常/问题摘要（条数或首条）  
- 未解决问题数（>0 时突出）  
- 查看详情  
- @ 指定人员  

### UI 参考关键词（来自图片）
- 蓝顶栏、白卡片、异常红字  
- 维度列表可点入  
- 问题状态绿标「已解决」  
- 底栏主按钮「分享工作日报」→ 本期改为分享企微卡片
