# 粮巴巴客户画像框架

> 面向：产品 / 运营 / 销售 / 数据  
> 用途：统一「我们服务的是谁」，支撑拜访、转化、产品组合与内容策略  
> 原则：框架可复用；具体人物卡按本框架填写，不与口径文档冲突时对齐 CRM 标签

---

## 1. 这是什么

粮巴巴的客户主体是**养殖侧决策人与经营主体**（养殖户、二批商等），不是 C 端消费者。画像要回答四件事：


| 问题        | 说明                                  |
| --------- | ----------------------------------- |
| 他是谁       | 角色、养殖规模与品类、决策方式                     |
| 他处在哪一段关系里 | 线索 → 注册 → 机会点 → 新客 / 老客             |
| 他值多少、爱买什么 | 价值分层 + 品类偏好（预混 / 玉米豆粕 / 动保 / 鸡蛋物流等） |
| 怎么跟他成交、复购 | 动机、顾虑、关键节奏、成功信号                     |


**画像 ≠ 客户标签堆砌**：标签是数据字段；画像是「解释这些标签背后的人」的模板。

## 2. 分型正交轴（先分型，再填人）

填写任何画像卡之前，先在四条轴上各选一格（可多标签叠加，但主型只留一个）。

### 2.1 生命周期轴（关系深浅）


| 分型     | CRM / 口径对齐  | 画像重点           |
| ------ | ----------- | -------------- |
| 线索     | 未注册 / 未进站   | 获客渠道、首次信任障碍    |
| 已注册未成交 | 注册但无预混成交    | 卡点（价、物流、服务、竞品） |
| 机会点    | 有审核通过机会点    | 跟进节奏、方案匹配      |
| 新客     | 当月预混新客      | 首单体验、二次下单      |
| 老客     | 历史有预混成交且非新客 | 复购、扩品、防流失      |




### 2.2 价值分层轴（量级）


| 分型     | 口径（预混折算，近 3 月）       | 互动策略倾向       |
| ------ | -------------------- | ------------ |
| 头部     | 月均 ≥5 吨，≥2 月成交       | 深耕、专属服务、组合政策 |
| 腰部     | 月均 2–5 吨（含 2），≥2 月成交 | 升舱、稳定复购      |
| 尾部     | 有成交但非头/腰             | 提频、防沉睡       |
| 3 月未成交 | 近 3 月无预混             | 唤醒 / 资格再判断   |




### 2.3 业务标签轴（场景）

与现网 channel / 名单对齐，一个客户可多标，画像里标「主场景」：


| 标签        | 典型经营场景       | 产品叙事入口       |
| --------- | ------------ | ------------ |
| KA        | 规模大、议价强、组织采购 | 供货稳定、账期、专属经理 |
| 核心养殖户     | 区域标杆养殖       | 实证、口碑、方案深度   |
| 白条        | 屠宰 / 白条流通相关  | 链条协同、节点时效    |
| 收蛋        | 产蛋 / 蛋品流通    | 料蛋比、收蛋服务、物流  |
| 处理鸡粪 / 收粪 | 粪污处理需求       | 环保合规、配套服务    |
| 实证        | 可对外讲故事的案例场   | 参观、内容、转介     |




### 2.4 养殖与品类轴（养什么、买什么）


| 维度      | 常见取值（按业务扩展）        |
| ------- | ------------------ |
| 畜种 / 品种 | 蛋鸡、肉鸡、其它禽畜…        |
| 存栏规模    | 羽数 / 批次 / 栏位数      |
| 主营采购    | 预混料、玉米、豆粕、动保、物流服务… |
| 忠诚品类    | 哪一类已习惯在粮巴巴下单       |
| 空白品类    | 有客情但未成交的品类（扩品机会）   |

## 3. 单张画像卡结构（必填模板）

每张人物卡按下列模块填写；空着比硬编好。

```text
【画像 ID】Personas-XXX
【主型】生命周期 × 价值层 × 主场景  （例：老客 × 腰部 × 收蛋）
【一句话】谁 + 关键场景 + 核心诉求 （≤30 字）

--- 基本画像 ---
- 称呼 / 角色：场东 | 场长 | 采购 | 其它
- 区域 / 站点归属：
- 决策方式：一人拍板 | 夫妻共商 | 公司采购流程
- 信息渠道：业务员拜访 | 站长 | 同行 | 企微/APP | 其它

--- 经营实况 ---
- 养殖类型与规模：
- 当前痛点（最多 3 条）：
- 成功标准（他怎么定义「划算」）：料比 / 产蛋率 / 到货准点 / 价格 / 服务…

--- 供需关系 ---
- 已成交品类：
- 潜在扩品：
- 竞品 / 替代方案：
- 价格敏感度：高 | 中 | 低
- 服务敏感度：高 | 中 | 低

--- 行为与触点 ---
- 偏好触达：实地拜访 | 电话 | 企微 | 下单页
- 理想拜访节奏：
- 下单触发点：缺料、换季、疫病、政策、活动…
- 流失风险信号：久未下单、抱怨物流、竞品地推…

--- Jobs / 阻力 / 金句 ---
- Job-to-be-done：（完成什么任务才找粮巴巴）
- 主要顾虑：
- 可用话术锚点：（一句他听得懂的收益）

--- 对内使用 ---
- 适配销售动作：首访 / 方案 / 促单 / 复购 / 扩品 / 挽回
- 关联数据字段：（lifecycle / channel / 头腰尾 / 名单…）
- 反例：不像本画像的特征（避免误贴标签）
```

## 4. 建议的种子画像清单（先建 6–8 张）

优先覆盖「量大或难转化」的交叉，避免只画一种「理想大客户」。


| ID 建议 | 主型组合               | 为何优先       |
| ----- | ------------------ | ---------- |
| P01   | 线索 × 潜在腰部+ × 核心养殖户 | 拓客话术与首访清单  |
| P02   | 已注册未成交 × 任意        | 转化瓶颈分析     |
| P03   | 机会点 × 头部/腰部        | 方案跟进 SLA   |
| P04   | 新客 × 腰部            | 首月履约与二次下单  |
| P05   | 老客 × 头部 × KA       | 保供与组合政策    |
| P06   | 老客 × 腰部 × 收蛋       | 预混+收蛋/动保扩品 |
| P07   | 老客 × 尾部 / 近 3 月未成交 | 唤醒与降本触达    |
| P08   | 白条或收粪主场景           | 垂直场景专项     |


每张卡填完后，用真实客户样例（脱敏）挂 1–2 个「黄金样例」，供销售质检与培训。

## 5. 怎么用（落地场景）


| 场景      | 用法                                 |
| ------- | ---------------------------------- |
| 拜访前     | 按主型选话术与必带物料；头腰深聊方案，尾部/未成交先探因       |
| 产品 / 活动 | 按画像测：谁会动、谁无感、会不会伤老客                |
| 内容 / 助手 | 话术按「痛点 → 证据 → 行动」套画像金句             |
| 数据看板    | 画像主型 ↔ CRM 标签可映射；看的是覆盖率与转化差，不是自拍人设 |
| 质检      | 抽检拜访是否匹配画像策略（拜访了谁 vs 该拜谁）          |

## 6. 填写与维护规则

1. **主型唯一、标签可多**：一张卡一个主型交叉，避免「既是线索又是老客」。
2. **写可观察行为**：少写「重视品质」空话，多写「换新玉米后先问酶制剂」。
3. **与口径同源**：生命周期、头腰尾、KA/核心/白条/收蛋/收粪等以业务口径与 CRM 为准；画像只解释、不另立一套矛盾定义。
4. **季度回顾**：根据转化与流失数据淘汰失效画像，合并过细分型。
5. **脱敏**：对外材料去掉真实手机号、精确地址；对内样例用客户 ID。

---



## 7. 一页速查

```text
粮巴巴客户画像 = 
  生命周期（线索/注册未成交/机会点/新客/老客）
  × 价值（头/腰/尾/近3月未成交）
  × 场景（KA/核心/白条/收蛋/收粪/实证）
  × 养殖与品类（养什么、买什么、还能扩什么）
  + 一张人物卡（动机、顾虑、触点、话术、数据映射）
```
