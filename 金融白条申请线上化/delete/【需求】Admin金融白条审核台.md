# 【需求】Admin · 金融白条审核台

> **范围**：仅 Admin「金融白条审核台」列表与详情（查看 / 编辑 / 初审审核 / 正式审核）本页。客户端初审/正式补件、业务端尽调填写、白名单配置、启用审核、额度配置、消息卡片文案等**不在本文**（仅作只读关联说明）。  
> **原型**：`步骤1_金融初审审核.html`  
> **入口**：粮巴巴管理系统 → 白条 → 侧栏「白条审核台」。  
> **背景**：客户初审提交后进入本台人审；初审通过后由业务员尽调 + 客户正式补件，再回本台做正式进件审核；通过后可推送银行。仅「初审通过」后客户才可正式进件；未过初审不可进入正式进件审核。

### 2.4 正式进件通过校验（详情审核）

须同时满足：

1. 客户正式进件资料状态=已提交；  
2. 经营性流水邮箱已收到；  
3. 若产品=全价料：百行征信已齐；  
4. 若额度 ≥30 万：实控人征信报告已齐；  
5. 正式进件必传附件无缺失项；  
6. 业务员尽调资料状态=已提交（非未提交 / 暂未提交）。

## 4. 状态字段（平台 / 银行拆分）

> **平台审核状态**与**银行状态**为两个独立字段。状态 Tab、列表「平台审核状态」列、评审筛选只使用平台态；银行结果不占用平台态枚举。原型内部码可与括号内旧名并存，对用户只展示新名。

### 4.1 平台审核状态

| 展示名 | 说明（本台视角） |
| --- | --- |
| 初审草稿 | 客户未完成初审提交（内部码：初审资料上传中） |
| 初审审核中 | 可【初审审核】；通过→正式进件草稿；驳回→初审驳回（内部码：初审待审核） |
| 初审驳回 | 不可正式进件；客户改完重提后→初审审核中（**不是**回草稿） |
| 正式进件草稿 | 等待客户正式件 + 业务员尽调齐备后进入审核（内部码：正式进件补件中） |
| 正式进件审核中 | 可【正式审核】；通过→正式进件审核通过；驳回→正式进件审核驳回 |
| 正式进件审核通过 | 可【推送银行】；推送后**平台态不变**，仅更新银行状态与上银/锡商明细（内部码：正式审核通过） |
| 正式进件审核驳回 | 客户/业务员按原因重提后再次进入审核流（内部码：正式审核驳回） |

### 4.2 银行状态

| 展示名 | 内部码 | 说明 |
| --- | --- | --- |
| — | — | 尚未推送银行（正式进件审核通过之初，或未到推送阶段） |
| 银行审批中 | 审批中 | 至少一家银行已推送且整体尚未落地开通/拒绝 |
| 白条已开通 | 已开通 | 银行审批通过并开通白条 |
| 银行拒绝 | 拒绝 | 银行审批拒绝；可【通知客户和销售】 |

> 上银/锡商「是否已推送 / 审批结果」仍为分行明细；「银行状态」为单据级汇总展示。双行明细与汇总的优先级规则实现期可细化（原型以 `bankStatus` 字段维护）。

### 4.3 关键流转（示意）

```
初审草稿 → 初审审核中 → 初审驳回 ⇄（改完重提）初审审核中
                    ↓通过
              正式进件草稿 → 正式进件审核中 → 正式进件审核驳回 ⇄ 重提
                                    ↓通过
                          正式进件审核通过  +  银行状态：— → 银行审批中 → 白条已开通 / 银行拒绝
```

## 6. 边界与异常

1. 未登录 / 无金融审核权限：不可进入本台。  
2. 非「初审审核中」不可点初审通过；非「正式进件审核中」不可点正式进件通过。  
3. 正式进件通过时资料未齐：按钮禁用或提交拦截并提示。  
4. 驳回 / 银行拒绝通知：原因为空不可确认。  
5. 推送银行：仅「平台审核状态=正式进件审核通过」；已推送不可重复推送同一银行；额度必填；推送不改变平台态。  
6. 网络失败可重试；附件预览失败提示重试。  
7. 查看/编辑/审核三种模式字段结构一致，仅底栏与可点操作不同。  
8. 状态 Tab / 评审筛选不得再出现「已推送银行 / 白条已开通 / 银行拒绝」作为平台态选项。
