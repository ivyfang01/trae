# 【需求】正式进件 · 消息通知（⑧⑨⑩⑪）

> **范围**：正式进件及相关落地消息：**⑧ 催客户补正式件**、**⑨ 催金融审核**、**⑩ 正式审核结果**、**⑪ 上银开通后通知金融 + 业务员**。初审阶段消息 ①～⑦、锡商开通等其他银行拒绝通知等**不在本文**。  
> **原型**：`步骤1_消息通知卡片.html`（§8～§11）  
> **通道总则**：除 **⑨、⑪-金融 走钉钉群** 外，**其余均为企微群通知**（⑧、⑩、⑪-业务员）。  
> **关联**：触发页见《【需求】业务端申请资料填写》《【需求】客户端正式进件资料补充》《【需求】Admin金融白条审核台》；本文只定触发、对象、通道、文案与跳转。

---

## 1. 总览

| 编号 | 触发时机 | 接收方 | 通道 | 目的 |
| --- | --- | --- | --- | --- |
| ⑧ | 业务员尽调资料**首次提交成功** | 客户所在企微群（或客户企微触达） | **企微群** | 提醒客户补充正式进件资料 |
| ⑨ | 业务员尽调 **且** 客户正式补件**均已提交成功**（齐备进入「正式进件审核中」） | 金融审核钉钉群 | **钉钉群** | 提醒金融人员尽快正式审核 |
| ⑩-通过 | Admin 正式进件审核**通过** | 销售员、客户（各自企微群/触达） | **企微群** | 告知通过，提醒去申请白条 |
| ⑩-驳回 | Admin 正式进件审核**驳回** | 销售员、客户 | **企微群** | 告知驳回原因，引导改资料重提 |
| ⑪-金融 | 银行状态变为**白条已开通**，且合作银行为**上海银行** | 金融审核钉钉群 | **钉钉群** | 提醒金融审核人员联系客户启用白条 |
| ⑪-业务员 | 同上（同步触发） | 业务员（企微群/触达） | **企微群** | 告知开通，请配合跟进启用 |

> **通道硬规则**：⑨、⑪-金融 → 钉钉群；⑧、⑩、⑪-业务员 → 企微群。不得混用。

## 2. 消息明细

### 2.1 ⑧ 请补充正式进件资料

| 项 | 说明 |
| --- | --- |
| **触发** | 业务员在申请资料页【提交】尽调成功（见业务端尽调 PRD）。同一工单尽调已提交过再改再提：是否重发见 §4 待确认；默认**仅首次提交**发一次。 |
| **接收方** | 客户（企微群；可 @ 客户或发群卡片，实现与现网企微策略对齐） |
| **通道** | **企微群**（非钉钉） |
| **标题** | 请补充正式进件资料 |
| **正文** | 业务员已为您提交白条尽调资料。<br/>请尽快补充正式进件资料（如经营性流水、财产证明等），提交后进入金融正式审核。 |
| **主按钮** | 【去补充资料】→ 客户端「正式进件资料补充」页（带客户/工单上下文） |
| **不发** | 不通知金融、不发钉钉 |

### 2.2 ⑨ 正式进件待审核

| 项 | 说明 |
| --- | --- |
| **触发** | 下列条件**同时满足**时发一次：① 业务员尽调已提交；② 客户正式进件资料提交成功；③ 工单进入「正式进件审核中」。若客户先交正式件、销售后交尽调，则在**后提交的一方成功时**判断齐备并触发。驳回后双方重提再次齐备时**可再发**（等同新一轮待审）。 |
| **接收方** | 金融审核人员所在**钉钉群** |
| **通道** | **钉钉群** |
| **标题** | 正式进件待审核 |
| **正文** | 客户 **{客户名称}** 业务员尽调资料与客户正式进件资料均已提交。<br/>业务员：{业务员姓名} · 请尽快完成正式进件审核。 |
| **主按钮 / 链接** | 无（纯文本提醒，不提供跳转按钮） |
| **不发** | 不发企微给客户/销售（客户侧已在正式件提交成功页获知；销售可用业务端进度查看） |

### 2.3 ⑩ 正式进件审核结果

#### 通过

| 项 | 说明 |
| --- | --- |
| **触发** | Admin 详情正式审核【正式进件通过】成功 |
| **接收方** | **销售员** + **客户**（各发一条或同群 @，实现与现网一致；通道均为企微） |
| **通道** | **企微群**（非钉钉） |
| **标题** | 正式进件审核已通过 |
| **正文** | 客户 **{客户名称}** 正式进件审核已通过。<br/>请尽快引导客户去申请白条（按合作银行：上银 APP 申请 / 等待锡商推送开通）。 |
| **按钮** | 无（纯文本提醒，不提供跳转按钮） |
| **平台态** | 正式进件审核通过；银行状态仍可为「—」，推送银行不在本消息内完成 |

#### 驳回

| 项 | 说明 |
| --- | --- |
| **触发** | Admin 正式审核【驳回】或列表【平台审核拒绝】且落「正式进件审核驳回」成功 |
| **接收方** | **销售员** + **客户** |
| **通道** | **企微群** |
| **标题** | 正式进件审核被驳回 |
| **正文** | 客户 **{客户名称}** 正式进件审核驳回。<br/>原因：{驳回原因}，请按原因修改资料后重新提交。 |
| **主按钮** | 【去修改资料】→ 客户进正式进件补件页回填；销售可进业务端尽调/档案协助（按驳回项归属） |

### 2.4 ⑪ 上海银行开通后 · 联系客户启用白条

> 同一触发下发 **两条**：金融钉钉 + 业务员企微；均无跳转按钮。

#### ⑪-金融（钉钉群）

| 项 | 说明 |
| --- | --- |
| **触发** | 工单银行状态变为**白条已开通**，且该笔合作为**上海银行**（含上银路径开通回传）。锡商开通不发。同一工单开通成功**只发一次**。 |
| **接收方** | 金融审核人员所在**钉钉群** |
| **通道** | **钉钉群** |
| **标题** | 上海银行白条已开通，请联系客户启用 |
| **正文** | 客户 **{客户名称}** 上海银行白条已开通。<br/>业务员：{业务员姓名} · 请尽快联系客户完成白条启用。 |
| **主按钮 / 链接** | 无 |

#### ⑪-业务员（企微群）

| 项 | 说明 |
| --- | --- |
| **触发** | 与 ⑪-金融相同，**同步触发** |
| **接收方** | **业务员**（企微群或业务员触达，与现网一致） |
| **通道** | **企微群** |
| **标题** | 上海银行白条已开通，请配合启用 |
| **正文** | 客户 **{客户名称}** 上海银行白条已开通。<br/>金融审核人员将联系客户启用白条，请同步跟进配合。 |
| **主按钮 / 链接** | 无 |
| **不发** | 不单独再发客户（启用由金融联系，业务员配合） |

## 3. 时序（示意）

```
业务员提交尽调 ──⑧企微──► 客户补正式件
                              │
客户提交正式件 ──(齐备)──⑨钉钉──► 金融审核群
                              │
                    Admin 正式通过 / 驳回
                              │
                         ⑩企微 ──► 销售 + 客户
                    （通过：提醒去申请白条）
                              │
                    上银开通成功（银行态=白条已开通）
                              │
                    ┌─⑪钉钉──► 金融审核群（联系客户启用）
                    └─⑪企微──► 业务员（配合跟进启用）
```

---

## 4. 边界与异常

1. 通道错误：⑨、⑪-金融 不得改发企微；⑧、⑩、⑪-业务员 不得改发钉钉。  
2. 重复发送：⑧ 默认尽调首次提交只发一次；⑨ 每一轮进入「正式进件审核中」发一次；⑩ 每次审核结论发一次；⑪ 上银开通成功金融与业务员各发一次。  
3. 群配置缺失 / 机器人失败：记失败日志，支持重试；不阻断提交/审核/开通主流程成功回执。  
4. 客户无企微触达：降级策略与现网一致（待确认：短信 / 仅销售代达）。  
5. 文案中客户名、业务员名、驳回原因取工单实时字段；无值不展示空占位句。  
6. ⑪ 仅上海银行；锡商开通不触发。

## 5. 待确认

1. ⑧ 尽调修改后再次提交是否重发企微。  
2. ⑩ 销售与客户是各发独立卡片，还是同一企微群 @ 双方。  
3. 【去申请白条】上银 / 锡商具体落地页是否与银行分流 PRD 同一套。  
4. 钉钉群、企微群的群 ID / 机器人配置归属（金融群 vs 客户群 vs 销售群）。  
5. 「启用白条」的具体动作口径（电话指导 / Admin 操作 / 客户端激活页）是否需在文案中写死。
