## 1. 背景和目标

### 1.1 背景

粮巴巴豆粕撮合/自营业务中，供应商在企微群发送上游开单截图，客户凭图派司机去油厂提货。截图版式因上游不同而不一，字段组合不固定；截图与提货单为**多对多**（拼车：1 图多单；拼采购：1 单多图）。

**一期**已完成：企微右侧上传 → OCR → 运营手工关联提货单 → 找客户群发送（脱敏/@）；找不到群走客服钉钉兜底；提供待匹配/已匹配/已关联提货单列表。客服「找群转发」已基本解放。

**当前痛点**：运营仍需从供应商群找图、手工上传、再手工关联。日均约 **4 人 × 1.5 小时** 消耗在找图与关联上，无法全流程无人值守。

### 1.2 目标

1. 白名单供应商群内开单截图**自动入库**（含 AI 判图、多行切片）并进入一期 OCR  
2. 匹配结果**唯一**时**自动关联**并**自动发送**客户群（复用一期发送逻辑）  
3. 失败时**钉钉机器人**及时通知开单截图运营，引导至待匹配列表手工处理（一期逻辑）  
4. 按群白名单**逐步切入**上线  

### 1.3 目标用户

| 角色 | 用途 |
| --- | --- |
| 开单截图运营 | 主用户；接收失败提醒，在待匹配列表兜底 |
| 系统/机器人 | 抓图、判图、切片、OCR、自动关联与发送 |
| 客服（钉钉兜底） | 仅沿用一期「找不到客户群」场景，本期不改 |

### 1.4 成功指标

| 指标 | 目标 |
| --- | --- |
| 自动关联成功率 | ＞ 80% |
| 运营工时节省 | 约 4 人 × 1.5 小时/天 |
| 人工处理张数 | 尽量趋近 0 |
| 失败可感知 | 需人工时钉钉及时提醒，并给出失败原因 |

### 1.5 名词释义

| 名词 | 说明 |
| --- | --- |
| 开单截图 | 上游/油厂开单结果截图，客户凭此提货；仅服务豆粕 |
| 群白名单 | 配置开启自动抓图的供应商企微群列表 |
| 切片 | 一张图含多条开单行时，裁成多张单行图再 OCR |
| 唯一候选 | 一期匹配规则过滤后，仅剩 1 条可关联提货单 |
| 待匹配列表 | 一期企微页签；未关联截图入口，本期增加「未匹配原因」 |

### 1.6 不做（Out of Scope）

- 找不到客户群的新方案（沿用一期客服钉钉）  
- 非白名单群自动抓图  
- AI 判定非开单截图进入 OCR/关联  
- **多候选自动关联**（拼车等一律人工）  
- 待匹配列表增加「来源群」字段（本期不加）  
- 改一期匹配硬规则本身（仅增加自动触发与失败原因展示）

## 2. 需求方案

### 2.1 功能流程图

```mermaid
flowchart TD
  A[白名单群内出现图片消息] --> B[图片落本地]
  B --> C{AI: 是否开单截图?}
  C -->|否| D[丢弃/仅日志 不提醒]
  C -->|是| E{是否多条开单行?}
  E -->|是| F[自动切片为多张]
  E -->|否| G[原图]
  F --> H[逐张进入一期 OCR]
  G --> H
  H --> I{OCR 成功?}
  I -->|否| J[进待匹配列表<br/>原因=OCR失败]
  I -->|是| K[一期匹配规则筛提货单]
  K --> L{候选数量}
  L -->|0| M[进待匹配列表<br/>原因=0候选]
  L -->|≥2| N[进待匹配列表<br/>原因=多候选]
  L -->|1| O[自动关联]
  O --> P[自动发送客户群<br/>一期脱敏/@逻辑]
  P --> Q{找到客户群?}
  Q -->|是| R[发送成功<br/>落入已匹配/已关联]
  Q -->|否| S[一期客服钉钉兜底<br/>本期不改]
  J --> T[钉钉机器人通知运营]
  M --> T
  N --> T
  U[上传/入库失败] --> V[钉钉发图+群名+失败说明]
  T --> W[运营打开待匹配列表手工关联]
```

### 2.2 需求列表

| 分类（产品模块） | 主要功能点 | 功能点拆分 | 优先级 |
| --- | --- | --- | --- |
| 群配置 | 白名单按群切入 | 配置启用/停用自动抓图的供应商群；未配置群保持一期纯手工 | P0 |
| 自动抓图 | 群图入库 | 监听白名单群图片 → 落本地 → 记录来源群（内部用，列表不展示来源群） | P0 |
| AI 判图 | 识别是否开单截图 | 覆盖多样式表格（预约表/拼单多行/ERP 单据等）；非开单图不进后续 | P0 |
| 自动切片 | 一图多行 | 检测到多条开单信息则切片；每张切片独立 OCR/匹配/关联 | P0 |
| 自动关联 | 唯一候选自动关联 | 复用一期匹配规则；仅候选=1 时自动关联（含吨数不一致/无吨数） | P0 |
| 自动发送 | 关联后自动发 | 跳过一期「是否发送」弹窗；直接走一期发送；找不到群走一期钉钉 | P0 |
| 待匹配增强 | 未匹配原因 | 列表展示失败原因；**不增加来源群字段** | P0 |
| 失败提醒 | 钉钉机器人 | 上传失败 / 关联失败通知开单截图运营；引导去待匹配列表 | P0 |

### 2.3 与一期关系

| 能力 | 一期 | 二期 |
| --- | --- | --- |
| 截图识别 / 待匹配 / 已匹配 / 已关联提货单 | 已有四页签 | **复用**，不新做列表页 |
| OCR 字段与匹配规则 | 已有 | **沿用** |
| 手工关联与发送弹窗 | 已有 | 人工路径沿用；自动路径跳过确认直接发送 |
| 上传入口 | 仅手工拖拽 | **新增**自动入库；手工保留 |

## 3. 需求明细

### 3.1 群白名单配置

| 项 | 说明 |
| --- | --- |
| 配置内容 | 企微群 ID/群名、是否启用自动抓图、启用时间、操作人 |
| 行为 | 仅启用群内图片进入自动流程；关闭后新消息不再自动处理，已入库数据不受影响 |
| 上线策略 | **一个个群逐步切入**，先少后多 |

### 3.2 自动抓图与 AI 判图 / 切片

| 步骤 | 逻辑 |
| --- | --- |
| 抓取 | 白名单群图片消息落本地存储；记录来源群（供钉钉文案与排障，**待匹配列表不展示来源群**） |
| AI 判图 | 判断是否开单截图。样式参考 `ref-开单样式1~6`，但**不限于**样例：宽表预约行、精简行、同车牌多行拼单、ERP 单据表等。判为否：不进 OCR，默认不钉钉打扰（可打日志） |
| 切片 | 一图含 ≥2 条开单行（如同车牌下多行「豆粕43% / 袋装50kg / 吨数」）→ 自动裁成多张单行图，再分别 OCR |
| 上传失败 | 落库/传 OCR 失败时：钉钉机器人把**图片**发给开单截图运营，并注明**哪个群**、失败说明 |

### 3.3 自动关联（核心）

匹配规则**完全复用一期**（摘要）：

1. 提货状态=提货中；东耀商家**非极速达**提货单  
2. 车牌必须一致（换车后用新车牌）  
3. 司机姓名/手机/身份证：截图有值则必须一致；空可跳过  
4. 供应商简称：提货单简称须为截图提货简称的**子集**  
5. 吨数：\|已关联截图吨数合计 + 本次识别吨数 − 提货单总吨数\| ≤ 0.3 为一致（软标）  
6. 蛋白、包装：识别出则必须一致，否则剔除；未识别可入候选  

**自动关联判定：**

| 候选结果 | 吨数 | 系统行为 |
| --- | --- | --- |
| 恰好 1 条 | 一致 / 不一致 / 截图无吨数 | **自动关联** |
| ≥ 2 条 | 任意 | **不自动**，进待匹配，原因=多候选（拼车等） |
| 0 条 | — | **不自动**，进待匹配，原因=0 候选 |
| OCR 失败 | — | **不自动**，进待匹配，原因=OCR 失败 |

自动关联成功后：

- 提货单开单状态、是否已关联等字段变更**同一期点关联成功**  
- **不再弹**「是否发送给客户」；直接进入自动发送  

换车申请中 / 未核单等一期禁止关联的情况：不自动关联，进待匹配并给出原因（如「换车申请中不可关联」）。

### 3.4 自动发送

| 项 | 说明 |
| --- | --- |
| 发送内容 | 一期逻辑：脱敏（抹客户名、单价等）后发客户群并 @ |
| 找群 | 一期主体-群配置优先，否则微信客户列表「售后」群 |
| 找不到群 / 多售后群 | **一期客服钉钉兜底**，本期不改 |
| 结果落库 | 已匹配列表、已关联提货单；截图发送状态=已发送/按一期规则 |

### 3.5 待匹配列表增强

一期列表字段保留（时间、上传人、供应商、文件、OCR 摘要、查看结果、删除等）。

**本期新增：**

| 字段 | 说明 |
| --- | --- |
| 未匹配原因 | 枚举/文案，例如：OCR 失败；0 候选；多候选；换车申请中；未核单；上传失败转入 等 |

**明确不加：** 来源群（列表不展示；钉钉提醒文案中可带群名）。

点击「查看结果」→ 一期识别页，手工关联逻辑不变。

### 3.6 钉钉机器人失败提醒

**通道：** 钉钉机器人 → 通知**开单截图运营**（群或指定接收人，实现时与运营确认机器人配置）。

| 场景 | 通知内容要点 | 运营动作 |
| --- | --- | --- |
| 上传/入库失败 | 附带图片；群名；失败说明 | 可手工上传或排查 |
| 关联失败（0 候选 / 多候选 / OCR 失败 / 禁止关联等） | 「【群名】开单截图未关联成功，原因：xxx」；可附缩略图或文件链 | 打开企微【待匹配列表】→ 查看结果 → 一期手工关联 |

提醒时机：失败发生后尽快推送（实时/准实时）；同一张图同一原因避免短时间重复刷屏（实现可做去重窗口，如 5 分钟）。

## 4. 边界 / 异常场景

| 场景 | 处理 |
| --- | --- |
| 非白名单群发图 | 不自动处理 |
| AI 误杀真实开单图 | 运营可一期手工上传补救；需监控误杀率并迭代模型 |
| AI 误放非开单图 | 进入 OCR 后易 0 候选 → 待匹配+提醒；可迭代判图 |
| 切片错误（切多/切少） | 进待匹配人工；记录原因便于优化 |
| 一图切片后部分成功部分失败 | 成功的自动关联发送；失败的分别提醒+待匹配 |
| 自动发送瞬时失败（非找不到群） | 关联可保留；钉钉提醒运营在已关联提货单补「发送」；原因记发送失败 |
| 重复图片 | 沿用一期：待匹配不重复；已关联过同图同单不重复关联 |

## 6. 附录

### 6.1 一期匹配规则原文位置

见 `开单截图自动化一期.md`「识别&匹配提货单」章节；本需求不修改规则口径，只增加自动触发条件。

### 6.2 风险

| 风险 | 缓解 |
| --- | --- |
| 样式长尾导致 AI/OCR 不准 | 按群灰度；样例持续补充；失败进待匹配不阻断业务 |
| 自动关联错单 | 仅唯一候选才自动；多候选强制人工；可抽检与回滚取消关联（一期能力） |
| 钉钉打扰过多 | 原因清晰；去重；非开单图默认不提醒 |

### 6.3 范围确认记录（产品）

- 仅豆粕；多对多（拼车/拼采购）  
- 自动关联：唯一候选即自动（含吨数不一致/无吨数）；多候选一律人工  
- 自动关联后自动发送；找不到群走一期  
- 抓图：落本地 → AI 判图 → 多行切片 → OCR；群白名单逐步切入  
- 待匹配：加未匹配原因，**不加来源群**  
- 失败提醒：**钉钉机器人 → 开单截图运营**
