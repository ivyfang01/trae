# 7月物流零碎需求文档

> **文档状态：** 待评审  
> **更新时间：** 2026-07-09  
> **产品模块：** 粮巴巴 · 物流系统  
> **涉及终端：** Admin 后台、钉钉端、司机端 APP / 小程序 / H5

---

## 一、背景

2026 年 7 月，物流业务在 **结算校验、运营导出、司机 onboarding、运单履约、提现体验、财务开票** 等环节存在若干体验与效率痛点，分散于 Admin 后台与司机端多个页面。本次整理 **7 项零碎优化需求**，覆盖：

- **结算侧**：装卸货净重与单据基准不一致时缺少预警
- **运营侧**：干线物流单无法按筛选全量导出、列表缺少运费发票入口
- **司机侧**：完善信息流程冗长、提交校验不明确、位置异常缺少调度联系方式、提现失败原因模糊

上述问题影响结算准确性、运营效率及司机端转化率，需在 7 月迭代中集中交付。

---

## 二、目标

| 目标 | 说明 |
|------|------|
| **降低结算差错** | 净重偏差 ≥ 1 吨时提交前红色提醒，减少错误结算 |
| **提升运营效率** | 支持按筛选项导出全部物流单，列表可直接查看运费发票 |
| **优化司机体验** | 完善信息分步引导、表单校验锚点、位置/结算/提现提示可理解、可操作 |
| **增强可联系性** | 位置异常、超距、结算环节展示 **派车调度电话**，支持一键拨打 |

### 5.1 R1 · 装卸货净重校验

#### 5.1.1 需求说明

豆粕、玉米、预混料的干线与末端物流，在 **提交申请结算** 时，校验装卸货磅单净重与单据基准净重是否一致。基准优先取 **提货单装货净重**；无提货单仅有 **发货单** 时，取 **发货单货物净重**。差值 **≥ 1 吨** 时红色提醒，**不阻断提交**。

#### 5.1.2 适用范围

| 维度 | 说明 |
|------|------|
| 品类 | 豆粕、玉米、预混料 |
| 物流类型 | 干线物流、末端物流 |
| 触发节点 | 提交「申请结算」时 |
| 终端 | 钉钉、Admin 后台 |

#### 5.1.3 校验规则

1. 分别取 **装货净重**、**卸货净重**（磅单值，单位：吨）。
2. 确定对比基准：

   | 优先级 | 条件 | 对比基准字段 |
   |--------|------|--------------|
   | 1 | 存在提货单 | 提货单 **装货净重** |
   | 2 | 无提货单，仅有发货单 | 发货单 **货物净重** |

3. 计算差值：`装货差值 = |装货磅单净重 - 基准净重|`，卸货同理。
4. 装货或卸货差值 **≥ 1 吨**（含等于）→ 触发红色提醒。

#### 5.1.4 提醒文案

装货、卸货超差 **分 2 条独立展示**：

**有提货单：**

| 场景 | 提醒文案 |
|------|----------|
| 仅装货超差 | 装货磅单净重与提货单装货净重相差 ≥ 1 吨，请确认后提交 |
| 仅卸货超差 | 卸货磅单净重与提货单装货净重相差 ≥ 1 吨，请确认后提交 |
| 均超差 | 上述 2 条同时展示，分装货/卸货模块 |

**无提货单、仅有发货单：**

| 场景 | 提醒文案 |
|------|----------|
| 仅装货超差 | 装货磅单净重与发货单货物净重相差 ≥ 1 吨，请确认后提交 |
| 仅卸货超差 | 卸货磅单净重与发货单货物净重相差 ≥ 1 吨，请确认后提交 |
| 均超差 | 上述 2 条同时展示 |

#### 5.1.5 交互说明

| 行为 | 说明 |
|------|------|
| 提醒样式 | 红色文字/提示条，位于装卸货模块底部 |
| 是否阻断 | 不强制阻断，仅提醒 |
| 实时校验 | Admin 编辑净重后建议即时校验 |
| 提交校验 | 申请结算时再次校验 |

#### 5.1.6 页面原型

![Admin 后台装卸货信息](./admin-装卸货信息.png)

![钉钉端装卸货信息](./钉钉-装卸货信息.png)

#### 5.1.7 示例

| 基准净重 | 装货磅单 | 卸货磅单 | 提醒 |
|----------|----------|----------|------|
| 10 吨 | 11.2 吨 | 10.1 吨 | 是（装货 1 条） |
| 10 吨 | 12 吨 | 8 吨 | 是（2 条） |
| 20 吨 | 21.5 吨 | 20.2 吨 | 是（装货 1 条） |

#### 5.1.8 验收标准

- [ ] 干线 + 末端结算申请均生效
- [ ] 有提货单 / 无提货单两种基准均正确
- [ ] 差值 ≥ 1 吨时钉钉、Admin 均红色提醒
- [ ] 双超差分 2 条提醒；差值 < 1 吨不提醒
- [ ] 不阻断提交流程

#### 5.1.9 已确认项

| 问题 | 结论 |
|------|------|
| 双超差展示 | 分 2 条提醒 |
| 阈值 | ≥ 1 吨（含等于） |
| 提货单字段 | 装货净重 |
| 无提货单字段 | 发货单货物净重 |

### 5.2 R2 · 干线物流订单 · 导出全部物流单

#### 5.2.1 需求说明

Admin 后台豆粕/玉米/预混料 **干线物流订单列表**，新增 **【导出全部物流单】**，按当前 **全部筛选项** 导出符合条件的 **全部订单**（不受 Tab、分页限制），导出字段沿用「导出详情」并 **新增订单状态列**。

#### 5.2.2 适用范围

| 维度 | 说明 |
|------|------|
| 品类 | 豆粕、玉米、预混料（**各品类独立模板，已有**） |
| 物流类型 | 干线物流 |
| 终端 | Admin 后台 |

#### 5.2.3 功能要点

1. 按钮位置：「导出详情」左侧（见原型）。
2. 导出范围：筛选项下 **全状态** 全部物流单。
3. 导出字段：**同导出详情** + **订单状态** 列。
4. 待结算阶段导出 **子状态**：待提交、待审核、审核通过（不导出「待结算」父状态）。

#### 5.2.4 订单状态枚举

待派单、待接单、已接单、待提交、待审核、审核通过、已完成、已关闭

#### 5.2.5 与「导出详情」差异

| 对比项 | 导出详情 | 导出全部物流单 |
|--------|----------|----------------|
| 数据范围 | 当前 Tab/列表 | 筛选项下全部 |
| 状态 Tab | 受限 | 不受限 |
| 字段 | 已有字段 | 同左 + 订单状态 |

#### 5.2.6 页面原型

![干线物流订单 · 导出全部物流单](./干线物流-导出全部物流单.png)

#### 5.2.7 验收标准

- [ ] 三品类各自模板均新增按钮
- [ ] 导出范围 = 筛选项全部订单
- [ ] 字段 = 导出详情 + 订单状态
- [ ] 待结算导出子状态
- [ ] 无数据有提示

#### 5.2.8 已确认项

| 问题 | 结论 |
|------|------|
| 品类模板 | 不同品类不同模板 |
| 待结算 | 导出子状态 |
| 导出字段 | 沿用导出详情 + 订单状态列 |

### 5.3 R3 · 完善信息 · 提交前表单校验与锚点定位

#### 5.3.1 需求说明

司机在 **完善信息** 页点击 **【同意提供上述信息进行审核】** 时，对全部必填项自上而下校验。未填或格式错误 → **红色提醒** + **锚点滚动至首个问题字段**，阻断提交。

> **关联 R7：** R7 分步后，本校验适用于 **Step 1「下一步」** 与 **Step 2 提交**。

#### 5.3.2 适用范围

| 维度 | 说明 |
|------|------|
| 页面 | 完善信息（承运资质审核） |
| 触发 | 同意提供上述信息进行审核 / Step 1 下一步 |
| 终端 | 司机端 |

#### 5.3.3 必填项（按校验顺序）

| 模块 | 必填内容 |
|------|----------|
| 身份证信息 | 人像面/国徽面、姓名、身份证号、登录/实名手机号 |
| 驾驶证信息 | 正页/副页 |
| 车辆信息 | 至少 1 辆车及必填子项、默认车辆 |
| 挂车证件 | 挂车行驶证、道路运输证、三人车合影（条件必填见待确认） |
| 协议 | 勾选同意 |

#### 5.3.4 锚点规则

- 定位第一个失败字段/模块顶部，平滑滚动
- 折叠车辆模块先 **展开** 再定位
- 多错误：首个锚点 + 其余同步红字

### 5.4 R4 · 司机端 · 装卸榜单与位置异常提醒

#### 5.4.1 需求说明

补齐司机上传装卸榜单、位置异常、运费结算环节的 **派车调度电话** 触达能力，并新增超围栏 **短信提醒**。

#### 5.4.2 子需求

**① 位置异常弹窗加调度电话**

- 触发：上传榜单 / 开始装卸货时位置异常
- 改造：弹窗增加 `派车调度电话：{phone}`，可点击拨打
- 电话来源：当前运单派车调度电话

**② 卸货磅单上传后 · 运费结算弹窗**

- 触发：卸货磅单上传成功
- 内容：提醒进入结算流程，展示派车调度电话
- 频次：每单 1 次

**③ 超电子围栏 5 公里 · 短信提醒**

- 触发：距装/卸货点 > 5km 且榜单未上传
- 方式：短信至司机登录手机号
- 内容含：运单号、装/卸环节、调度电话

![司机端 · 我的运单](./司机端-位置异常弹窗.png)

#### 5.4.4 验收标准

### 5.7 R7 · 完善信息 · 分步流程（实名开户 + 资质完善）

#### 5.7.1 需求说明

将 **完善信息** 拆为两步：先 **实名认证 + 开户**，再填 **驾驶证 + 车辆信息** 提交审核。

#### 5.7.2 整体流程

```
进入完善信息
    ↓
Step 1  实名认证 + 开户（手机号）
    ↓ 通过
Step 2  驾驶证 + 车辆信息
    ↓ 提交（沿用 R3 校验）
承运资质审核
```

#### 5.7.3 Step 1 · 实名开户

| 字段 | 必填 | 说明 |
|------|------|------|
| 身份证人像面/国徽面 | 是 | OCR |
| 姓名、身份证号 | 是 | OCR 回填 |
| 登录手机号 | 是 | 只读展示 |
| 实名手机号 | 是 | 调取验证，须本人实名 |

**逻辑：** 实名通过 → 触发锡商/上银开户 → 成功方可进入 Step 2。

#### 5.7.4 Step 2 · 驾驶证 + 车辆

- 驾驶证正/副页
- 车辆信息（车牌、车型、质量、挂车证件等）
- 三人车合影 + 协议勾选
- 提交：**同意提供上述信息进行审核**（R3 校验）

#### 5.7.5 断点续填

| 场景 | 行为 |
|------|------|
| Step 1 完成，Step 2 未完成 | 再次进入默认 Step 2 |
| Step 1 未完成 | 仅展示 Step 1 |
| 审核驳回 | 定位至对应步骤模块 |

#### 5.7.6 页面原型

![完善信息 · 现状](./完善信息-步骤拆分1.png)

![完善信息 · 车辆信息](./完善信息-步骤拆分2-车辆.png)

![完善信息 · 挂车证件与提交](./完善信息-步骤拆分2-证件.png)

#### 5.7.7 验收标准

- [ ] 2 步流程，步骤指示清晰

- [ ] Step 2 提交沿用 R3 校验

- [ ] 实名/开户失败有明确提示

#### 5.7.8 待确认项

| 问题 | 说明 |
|------|------|
