## 1. 产品概述

### 1.1 一句话定位
为物流运营提供的 B 端能力增强：在豆粕干线物流订单（豆粕寄售）上，司机上传装货磅单后即可审核并同步订单侧结算。

### 1.2 核心价值主张
将豆粕寄售场景的供应商结算节点从「卸货后审核」前移到「装货磅单审核通过」，缩短结算周期，提升寄售供应商合作意愿与满意度。

## 2. 背景与目标

### 2.1 业务背景
- **现状**：豆粕寄售物流订单需等到卸货后才审核磅单并与供应商结算，周期偏长。
- **痛点**：结算慢导致寄售供应商不愿合作。
- **机会**：司机上传装货磅单后，物流运营及时审核；通过后同步订单侧，即可按装货磅单数据推进供应商结算。
- **落地页面**：现有「豆粕干线物流订单」列表（筛选区 + 状态 Tab + 表格），本需求在其上增加「大宗业务类型」筛选，并在订单详情增加装货磅单审核。

### 2.2 产品目标
- **O**：加快豆粕寄售供应商结算速度，降低因结算慢导致的合作流失风险。
  - **KR1**：[建议值，待确认] 「装货磅单上传 → 审核完成」中位时长 ≤ X 小时。
  - **KR2**：[建议值，待确认] 装货磅单审核通过后，订单侧可结算比例 ≥ Y%。
  - **KR3**：[建议值，待确认] 钉钉提醒触达率可观测。

### 2.3 成功指标
- **北极星指标**：豆粕寄售订单从「装货磅单上传」到「订单侧拿到已确认装货磅单状态」的时长（中位数/P90）。
- **辅助指标**：装货审核通过率/驳回率；钉钉发送成功率；卸货时「补同步装货状态」订单占比。

**模块**：M-2｜**功能**：F-4

| 场景 | 行为 |
|------|------|
| 装货已审核并已同步 | 卸货审核时**不同步**装货确认状态 |

### 7.2 状态流转

```
装货磅单：未上传 → 待审核 → 已通过
                      ↘ 已驳回 → 重新上传 → 待审核
```

|------|------|

| 订单侧同步失败 | 提示失败，支持重试 |
| 筛选无结果 | 空状态 |

## 8. 功能详细设计

### M-1：消息通知

#### F-1：装货磅单审核钉钉提醒
- **描述**：豆粕寄售物流订单司机上传装货磅单后，向刘悦悦推送钉钉卡片。
- **来源**：JTBD-1
- **原型**：`钉钉卡片-装货磅单待审核.html`
- **卡片字段（MVP）**：
  - 标题：豆粕寄售装货磅单待审核
  - 物流订单号、车牌号、司机、粮点/装货地、货物、上传时间、业务类型「豆粕寄售」
  - 按钮：去审核（跳转订单详情）
- **规则**：仅大宗业务类型=豆粕寄售触发；接收人可配置（MVP：刘悦悦）。
- **异常**：发送失败不影响上传成功。

### M-2：装货磅单审核与同步

#### F-2：装货磅单审核
- **描述**：豆粕寄售物流订单详情增加装货磅单审核；通过后传装货磅单给订单侧。
- **来源**：JTBD-2, JTBD-4
- **入口**：订单详情装货磅单区「审核」；钉钉卡片「去审核」。
- **规则**：未上传不可审；通过后触发同步（F-4）。

#### F-4：装/卸货状态同步规则
- **规则（对齐 MRD）**：
  1. 装货磅单审核后 → 同步确认状态给订单侧。
  2. 卸货磅单审核时 → 若装货已同步，则不同步装货状态。
  3. 若装货未审核 → 卸货审核时继续更新装货审核状态给订单侧。
- **待确认**：「未审核」是否含已驳回、同步失败中。

### M-3：订单列表筛选

#### F-3：大宗业务类型 = 豆粕寄售
- **描述**：在「豆粕干线物流订单」筛选区增加「大宗业务类型」，可选「豆粕寄售」。
- **来源**：JTBD-3
- **原型**：`豆粕干线物流订单列表.html`
- **交互**：与现有筛选项样式一致；与查询/重置联动；可与状态 Tab、其他条件组合。
- **建议位置**：与「业务类型」「发货类型」「供应模式」等下拉同一行区域。
- **列表列**：沿用现有列（装货状态、物流订单号、发货单号、提货单号、是否寄售、是否货到付款、粮点、发货类型、货物、操作等）；本需求**不强制**新增表格列，审核入口在详情（若产品希望列表直达，可二期加「装货磅单审核」操作）。
